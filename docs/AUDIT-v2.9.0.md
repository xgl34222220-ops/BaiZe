# 白泽 2.9.0 清理优化

## 已确认原因

- 安装包后台默认保留 30 天；执行周期与保留天数是两种设置。
- 安装包实际挂在规则任务下，只调整缓存任务不会改变安装包周期。
- 扫描使用较广的共享索引，但删除仅允许八种固定目录；扫描结果可能无法删除。
- 旧自动安装包搜索仅到五层且使用 `find -mtime +N`，边界还会多保留接近一天。
- 共享索引先递归目录逐项启动 stat，再 find 一次；应用用户目录发现也重复访问已覆盖的 files/cache 树。
- 手动缓存扫描继承后台保留天数，导致近期缓存不显示。

## 本次修改

安装包独立定时、统一手动与自动路径规则、只查安装包扩展名、毫秒级 UI 状态不再逐文件落盘。支持多用户、工作资料、外置存储与应用下载/缓存目录。白名单及规范路径复查继续生效；系统安装目录不在扫描根内。扫描结果逐包列出名称、路径与体积，最多显示 500 行，总量不截断。

共享索引一次遍历后交给原生索引器读取元数据，TTL 校验同时检查副索引存在和时钟有效；读取失败保留旧完整索引，终止信号退出任务。归类补齐 UC、夸克、网盘、Telegram 等来源，仍沿用预览、冲突处理及撤销。

UI 统一提高辅助字号、点击区域和分组层次，卡片减少边框，以轻阴影区分。安装包周期、期限和快捷选择集中显示，首页与任务健康页显示安装包调度状态。

升级保留已有保留期限，安装包初始周期继承原规则任务；用户可在安装包计划设为每小时、不保留。手动缓存扫描显示当前缓存，自动缓存继续遵守配置期限。

## 本机验证

- 121 个安装包（含深层目录、酷安缓存、多用户、外置卷）实际扫描/删除测试通过。
- 保留期、白名单、扫描后新文件及父目录换为符号链接测试通过。
- 1500 目录 / 6000 文件，相同原生索引器与相同文件集合，完整索引从 6.022 秒降至 0.184 秒。此为 Linux 本机一次比较，不能作为 Android 实机速度承诺。
- 兼容清理 10 项测试通过，1 项可选基准跳过。
- Android 编译、正式签名与完整打包回归由 CI 作为发布前门禁。
