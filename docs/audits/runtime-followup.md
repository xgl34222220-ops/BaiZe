# 运行链路复查与修复

本次依据 v2.9.0 代码复查定时、任务启动、恢复和结果展示。范围不包含其他审查负责的规则内容、文件归类算法或 UI。

## 已确认问题及实际修复

1. **智能计划污染实际运行时间。** 旧控制器通过改写 `last_*_run.epoch` 延后任务，界面据此展示的“上次运行”可能是未来时间；切换严格间隔后旧的延后锚点仍然生效。现在完成戳仅由真实成功任务更新，智能建议保存为 `desired_due`。调度器和 App 采用相同有效性条件：智能模式、相同间隔、相同完成戳，以及两小时内且非未来的建议。改间隔、切换严格计划、控制器停更均不会被旧建议长期拖住。升级根据旧状态单独记录的 `last_actual_epoch` 恢复旧锚点；该字段是旧版本能提供的最近已知完成时间，无法追溯旧历史里没有记录的精确秒数。
2. **失败被当作“没有垃圾”。** 智能控制器曾把错误或停止任务的零字节结果计入低收益/零收益连续次数，进而把失败任务降频甚至延期数天。错误数非零、结果为停止/取消/失败/中断的记录现在不进入该学习过程。
3. **用户按停止后马上又重跑。** 取消只删除请求，没有推进或延期到期候选，下一秒又可能启动同一任务。现在间隔任务延期至下一周期，固定每日任务消费当前日期周期；延期不伪造成功完成戳。跳过同样不冒充清理成功。
4. **相同执行条件反复请求 Android 系统服务。** 每轮候选挑选/并行检查重复读取配置并反复执行 `dumpsys power/battery/deviceidle`。现在配置按轮快照读取，取值使用纯 shell 字符串操作且不 source 配置；系统条件按需在该轮各读取一次，下一轮继续反映设置和设备状态变化。
5. **启动窗口竞争。** 引擎获得删除锁前、深度扫描切到删除的间隙，另一个请求可能覆盖 `running.env/worker.env`。增加原子发布身份的启动锁和运行中 Worker 身份检查；识别 PID、启动 ticks 和任务命令。Runner 在执行引擎前回执，替代所有小任务都固定等待一秒的启动方式。任务 ID 限定为安全文件名字符。二次审查发现陈旧锁双竞争可能拆掉新拥有者，已通过持久 `.recovery` inode 的短暂 kernel flock 串行回收，并在取得锁后重新读取拥有者；Supervisor 同类路径一起修复。回收 guard 不应被日志清理或普通运行清理删除；进程退出由内核释放锁。
6. **重启守护导致完成任务重复执行。** 原来仅调度器在 wait 结束后写完成戳；执行中重启调度器会丢失成功完成记录。Runner 现在独立保存每组本次任务结果、结束时间和成功完成戳，固定每日周期通过环境传入。缓存并行通道写回共享完成状态。Supervisor 增加单实例锁，避免 App 恢复与开机服务同时拉起两个调度器。
7. **遗留结果误展示为当前清理。** 归类启动失败仍可读取上次 `organizer-result.env`，已改为调用前清除本次结果槽。App 统一结果收集只关联本次任务时间之后生成的最新汇总、明细、报告与覆盖；APK 结果不再混入上次应用缓存明细。累积总数仍是累计数。
8. **修复按钮/页面误拆真实锁。** Kotlin 原任务识别漏掉 APK、深度 manifest、并行缓存等脚本，部分恢复路径无条件删除 `running.env`。新增 `RuntimeTaskOwnership`，统一检查运行脚本与 PID 启动身份，拒绝已回收 PID、僵尸和无实际进程的旧状态。TaskCoordinator、RootService、调度修复和任务入口使用该识别，旧进度文件不再永久阻塞操作。
9. **清理后 TTL 索引仍是删除前内容。** Runner 和 App 直接执行入口在删除类任务结束后使共享索引元数据失效，包含部分失败和取消。下一次依赖索引的扫描会重新构建。各直接脚本的对应处理由规则/扫描审查补齐。
10. **App 时间展示与后台不一致。** 增加可单测的 `SchedulerTiming`，处理严格/智能建议、取消延期和墙上时钟回拨；修复跨午夜仍处于昨日每日计划宽限期时，App 错报要等待今天晚上。

## 验证

- `test-runtime-recovery.sh`：真实调度器验证智能建议不改完成戳、严格间隔忽略旧建议、每轮系统条件读取一次、取消不立刻重跑、时钟回拨恢复；真实 Worker 验证调度器缺席时持久化完成状态、删除索引失效、失败归类不复用历史成功、取消保存为 exit 9；并发启动两个 Supervisor 只运行一个 Scheduler。
- `test-stale-launch-race.py`：通过拦截 `ln/rm` 强制两个启动器都先看到同一个陈旧锁，并让第二个 unlink 晚于第一个新拥有者发布；验证只有一个实际 Runner 被启动，另一个返回忙碌。测试已通过。
- 更新 `test-autopilot-controller.sh`：模拟真实完成戳，验证低收益建议、空间压力、息屏延后与真实戳分离；失败记录不进入零收益休眠；严格模式迁移旧虚拟锚点。
- 已通过原调度公平性、兼容并行、安装包独立小时计划、固定七字段队列、执行中心跳、健康诊断与温度不阻断回归。
- 新增 JVM `SchedulerTimingTest` 和 `RuntimeTaskOwnershipTest`，交由统一 Android CI 执行；本文不预先声称该 CI 结果。
- 修改 shell 文件已通过 `sh -n`。

## 边界

本地 Linux 回归验证调度与任务状态行为，不代表安卓真机后台存活率或扫描耗时。进程命名空间与 `/proc` 在当前容器不完全一致，既有真实 `/proc` 锁验证需在正常命名空间的 CI/手机复核。未修改用户的全局自动开关、息屏/充电条件或配置间隔，也未移除安装包保留策略。
