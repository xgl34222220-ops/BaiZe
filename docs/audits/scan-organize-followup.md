# 扫描、安装包与文件归类复查

本轮针对 2.9.0 发布后提出的“整个模块没有全面优化”反馈，继续检查实际执行链。下列修改属于扫描与归类部分，不代替清理规则、调度、UI 的独立审查。

## 已修复的问题

| 位置 | 原问题 | 修改后的行为 |
| --- | --- | --- |
| 安装包快照 | 只保存路径，清理时只看文件是否比快照更新。同一路径替换新 APK 并保留原修改时间，可以被错误删除。 | 扫描同时保存设备、inode、大小、精确修改/变更时间；身份快照与目标清单分别校验摘要和条数。文件身份变化后跳过。旧格式需要重新扫描。 |
| 任务互斥 | 安装包任务不认识活跃的归类 worker，归类器未覆盖全部快照清理任务。 | 补齐相互识别，避免把这些活锁当作残留锁恢复。 |
| 共享索引 | TTL 只检查部分侧索引；更改大文件阈值或分类表后仍复用旧分桶。 | 校验所有侧索引与配置、分类表、来源配置和扫描范围签名；等待索引锁后再次检查是否可复用。 |
| 共享索引 shell 退路 | 每文件读取两次 stat；大写下载中间文件与原生路径过滤不一致；无扩展名文件可能误入归类桶。 | 一次 stat 同时取身份和大小；先统一后缀大小写；无扩展名明确不进入归类桶。原生/退路结果对齐。 |
| 存储诊断覆盖 | 原共享根只扫两层，DCIM/Camera、深层相册与自定义目录中的文件未进入存储统计、大文件和重复文件结果。 | 诊断请求使用独立的存储范围，遍历公开目录到 32 层；归类仍使用下载、接收、用户文件范围。应用缓存、数据库、链接仍按既有边界排除。 |
| 重复文件 | 忽略已有大小表，又逐文件 stat；每一个重复大小都重新扫描整张表。直接覆盖正式结果，失败可以留下半份报告。 | 复用原生尺寸表，大小分组后读 64 KiB 前缀，仅前缀相同的大文件再计算完整 SHA-256；小文件直接复用已经完整读取的前缀哈希。每层排序后线性分组；只在成功后替换报告。 |
| 存储分析 | Android 的非 Python 分支逐文件 stat，且带点目录、大小写和特殊文件名的扩展名处理不一致。空索引被当成错误。 | 原生尺寸表一次聚合，无需 Python、无逐文件 stat；按文件名统一扩展名；空文件独立统计，空存储正常返回空结果。 |
| 大文件 | 不建立索引，阈值未验证；逐文件 stat 两次，可能展示半份报告。 | 主动刷新完整索引、验证阈值；按统一尺寸表过滤，再一次 stat 校验候选。不会因共享大文件桶采用另一阈值而漏报。报告原子替换。 |
| 自动归类 | 每轮都从头读清单，前部存在不支持或同名冲突文件时，后续文件可能永远轮不到。 | 达到时间/数量预算后保存剩余 NUL 队列，下轮继续消费；当前队列完成后再发现下一批。 |
| 自动归类来源 | 手动来源新增了 UC、夸克、网盘、Telegram，自动兜底发现没有对应添加。 | 补齐这些公开来源与 Telegram 系应用媒体目录；仍需通过归类器的来源/资源文件校验。 |
| 归类索引失败 | 索引器出错后仍使用之前的清单；用户刚下载的文件被遗漏。有效的空归类桶也会触发额外扫描。 | 失败重新执行独立安全发现；成功的空桶正常视为无候选；手动预览主动刷新，避免在 TTL 内漏掉刚新增文件。 |
| 归类取消与移动 | TERM 清掉运行锁后脚本可能继续移动；同名冲突判定后出现的新目标可能被覆盖；输出目录软链接可导致改变外部目录权限。 | 信号转为停止标记，在事务边界收尾并保留已完成移动的撤销；使用不覆盖移动并验证实际完成；创建/改权限之前拒绝软链接输出目录。 |
| 变更后的索引 | 清理或归类完成后索引还可能在 TTL 内指向旧路径。 | APK 清理、归类移动、App 撤销成功后使索引元数据失效。 |

## 验证

新增/扩展的行为回归均已通过：

- `test-apk-coverage.py`：5 项，含 121 个安装包、多用户、外置卷、年龄/白名单、父目录替换、同路径替换、恢复 mtime、身份快照篡改。
- `test-storage-tools.py`：5 项，使用实际编译的原生索引；覆盖深层相册、大小写、特殊文件名、空文件、不同阈值、完整哈希区分、两组同大小重复文件、读取失败保留旧报告、TTL 失效。
- `test-organizer-continuation.py`：5 项，覆盖连续三轮穿过阻塞文件、索引失败后的新文件发现、自动来源一致性、软链接输出边界，以及发送真实 TERM 后已移动文件与撤销条目一致。
- 原有共享索引原生/退路对照、失败事务、增量索引、归类端到端、多用户来源、冲突策略、自动预算、媒体刷新、分类表及安装包保留规则回归通过。

以上为 Linux 行为夹具与 BusyBox shell 验证，不是实机速度承诺。重复文件全哈希仍与真正相同前缀的大文件字节数相关；公开存储诊断范围扩大会读取更多真实目录。未将只扫描部分目录的旧耗时与扩大覆盖后的耗时直接比较。重复文件、大文件和空间分析工具均只生成报告，不删除文件。
