# 白泽 3.3.3 正式版

本版在 3.0.0 正式版之上合入下载归类与性能工具修复（#235）、保护名单可解释与全功能审查（#234）、新图标「白泽晶」与弥散渐变玻璃启动页（#236）。内部构建号为 **30030**，沿用原 App 包名、模块 ID 和正式签名。

## 文件归类：跳过仍在下载的文件（#235）

- 修复「刚下载的视频无法播放」：很多下载器直接写最终文件名，归类此前可能在写入中途把文件搬走。现在模块与 App 两侧同一套三道闸：
  - **年龄门槛**：最近 `organizer_min_age_minutes` 分钟内修改过的文件不动（默认 10，范围 1–1440）。
  - **仍被打开**：每轮只扫描一次 `/proc/*/fd`，正在被写入或播放的文件本轮跳过，下次再归类。
  - **移动前复核**：移动前再核对大小与修改时间，发生变化就跳过。
- 此前已被搬走的文件在「内部存储/BaiZe归类/<分类>」，可在「文件归类」页点「撤销上次归类」放回原目录；下载中途被搬走的那份本身不完整，需要在原应用重新下载。

## 性能工具（实验）：不再误报（#235）

- **数据库优化改用系统 SQLite**：Root 下由同一 APK 经 app_process 用 Android `SQLiteDatabase` 执行 `integrity_check` → `REINDEX` → `VACUUM`，保持原日志模式，完成后恢复属主、权限与 SELinux 标签；安全闸不变（只处理未运行应用、跳过使用中/加密/超大/校验不通过的数据库，微信、QQ、TIM 与白泽默认在黑名单）。`sqlite3` 仅作兜底，不再显示「设备无 sqlite3」。新增「立即优化」。
- **多后端冻结检测**：只读探测 cgroup v2 进程级（含 apps 子树）、v2 frozen 分组、v1 freezer、系统 `am freeze` 四种方式；单个进程缺少节点只跳过该进程；不支持时给出准确原因；页面显示「冻结方式」并可「重新检测」。仍绝不用强制停止代替冻结，默认关闭，开机阶段不运行。

## 保护名单可解释与临时允许（#234）

- 结果行显示「已保留 · 命中保护规则：路径 … / 应用 …」，点开列出全部匹配规则。
- 用户规则可「临时允许本次」（仅此文件一次，仍需确认、仍进回收站，规则不变）或「从保护名单移除该规则」；白泽回收站内部目录显示「系统级保护，无法解除」。
- 移入回收站前先核对保护，全部受保护时显示原因，不再报「未确认移入回收站」。
- 设置 › 管理与维护新增「保护名单管理」；保护名单页新增「系统保护」标签。

## 全功能审查修复（#234）

- 已授权 Root 时，大文件、重复文件、截图、旧下载、聊天媒体、根目录整理、滑动整理等页面自动开启「所有文件访问」，失败或超时再打开系统设置。
- 免 Root 缓存清理进入即自动用 Root 核对保护名单，并区分「命中保护」与「尚未核对」。
- 模块在 Root 管理器中停用、待移除或刚安装未重启时，自动清理明确说明「自动任务暂不会执行」及解决办法。
- 照片瘦身入口只对 JPEG 显示；文件详情去掉嵌套滚动；用时显示「不到 0.1 秒」而不是「0.0 秒」。

## 根目录整理（#234）

- 白泽内部目录（`.baize-file-trash`、`.baize-quarantine`）不再列为候选或「受保护」，在底部「白泽内部」显示实际大小并可直达回收站；回收目录按需创建，清空后自动收起。
- 移除过又被应用重新创建的文件夹单独归入「被重新创建」分组，显示出现次数与可能的来源应用，可一键「禁止重建」或「忽略此文件夹」；不会自动禁止任何文件夹。
- 移除计数修正：以根目录下该名称是否真的不存在为准，提示条与撤销按顶层条目计数，与整理记录一致。

## 新图标与启动页（#236）

- 新应用图标「白泽晶」：白泽青渐变底上的磨砂玻璃六棱晶石、白泽角与星光，全部为手写矢量；同时提供 Android 13 主题（单色）图标。
- 弥散渐变玻璃启动页：白泽青色斑渐变底 + 玻璃光晕图标；Android 8–11 直接使用渐变窗口背景，Android 12+ 首帧淡入同一张渐变后淡出，总时长不超过 250ms，不新增 Activity、不拖慢冷启动。启动页底部品牌图更新为「白泽 / BAIZE · v3.3.3」。

## 安装与更新

- 仅更新 App：覆盖安装 `BaiZe-v3.3.3.apk`，不要先卸载旧 App。
- 使用定时自动清理：同时更新 `BaiZe-v3.3.3-Module.zip`，并按模块管理器提示重启。模块不会在开机时执行扫描。
- 模块内置 APK 与独立 APK 字节一致；下载同时提供 SHA-256 和正式签名证书信息。

## 验证范围

发布前执行 Android 单元/界面回归、lint、原生与 Shell/Python 回归、正式签名及版本检查、模块内外 APK 一致性，以及 Android 模拟器上实际签名包的安装、启动和覆盖升级。发布后核对 Release 与下载镜像实际字节，再更新 OTA。

HyperOS 等厂商 ROM 上实际使用的冻结方式、Root 下数据库优化后的应用启动，以及长期后台运行仍需实际设备观察；模拟器验证不能替代全部真机兼容性测试。
