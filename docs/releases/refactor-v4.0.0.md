# 白泽 4.0.0 正式版

本版在 3.3.3 正式版之上合入 3.3.3 设备反馈修复（#238）与发布前审查修复（#239）。内部构建号为 **30031**，沿用原 App 包名、模块 ID 和正式签名。

## 修复：计划设置保存失败「未知错误」（#238）

- 原因：App 校验配对模块时把模块版本写死为 `2.0.0`，3.x 模块（`version=v3.3.3`）因此被判定为「需要更新模块」，保存自动清理计划时只显示「未知错误」。
- 现在只按模块 ID 与内部构建号（`versionCode`）配对；版本不匹配时显示真实原因（例如「此清理任务需要配套 30031 模块（当前模块版本号 …）」），不再显示「未知错误」。

## 修复：定时任务每分钟重跑（#238）

- 任务跑完但有少数项目没删掉时，模块现在以退出码 **10（部分完成）** 结束：本周期视为已完成，下一次按设置的间隔执行，不再立即重试。
- 真正失败（引擎不可用、任务异常退出等）在同一周期内**最多重试 3 次**，之后顺延到下一周期，不会整天循环。
- 调度记录对退出码 10 显示「执行结束，部分项目未清理；原因见清理记录，下次按周期执行」。

## 记录不再误报「有异常」（#238）

- **跳过不再算异常**：保护名单命中、扫描后已变化、文件已不存在、目录太大/太慢（超过单目录时限）、目录无法完整读取、需要手动确认等，都记为「已跳过」，不是失败。
- 只有白泽尝试删除却被系统拒绝（没有权限、文件被占用、I/O 错误、删除超时等）才计为「失败」。
- 记录列表角标改为「失败 N 项」/「已跳过 N 项」两种，分别显示。
- 旧记录读取时重新分类：扫描类记录的错误数视为跳过；3.3.4 之前的清理记录在没有失败证据时显示为中性的「旧版本记录，未区分原因」。

## 新记录详情页（#238）

- 每条有遗留项目的记录都可以点开，逐项列出路径、大小、分类和通俗原因。
- 对单个项目：删除（优先移入回收站 / 隔离区，可恢复）、打开所在目录、复制路径、加入忽略、受保护项「临时允许本次」（保护名单本身不变）。
- 支持批量勾选删除；无法移入回收站的项目需要再次确认才会永久删除。
- 逐项明细只在任务结束时写入 `run-details/`：每次最多 200 行、只保留最近 30 次，受状态目录预算约束，开机阶段不写入、不扫描。

## 发布前审查修复（#239）

- **记录详情页安全边界**：被跳过的「整个目录」行（例如无法读取的 `/data/media`、太慢的 `Download`）只作说明，不再提供删除；存储根目录、标准公共文件夹（Android、DCIM、Download、Pictures 等）、`Android/data|obb|media` 以及整个应用数据目录一律不能从记录页删除。
- **快照校验超时不再算失败**：深度清理与缓存快照清理在删除前做内容校验，单个文件校验超时（超过 15 秒）现在记为「太慢，本次跳过」，文件原样保留；此前会计为失败，深度清理还会每次停在同一个文件上无法继续。
- **安装包清理**：文件已删除、只是媒体刷新记录写不进去（内部代码 70）时不再计为「失败 1 项」，改为说明「媒体刷新记录无法写入，本轮已提前停止」。
- **调度状态文案**：缓存与文件归类并行批次中，部分完成（退出码 10）不再显示「异常任务将自动恢复」。
- **首页文案**：一键扫描有引擎未完成时，首页显示「部分扫描未完成 / N 项扫描未完成，可稍后重新扫描」，不再显示「扫描有异常」。
- 启动页底部品牌图更新为「白泽 / BAIZE · v4.0.0」。

## 安装与更新

- 仅更新 App：覆盖安装 `BaiZe-v4.0.0.apk`，不要先卸载旧 App。注意：保存自动清理计划需要配套的 30031 模块。
- 使用定时自动清理：同时更新 `BaiZe-v4.0.0-Module.zip`，并按模块管理器提示重启。模块不会在开机时执行扫描。
- 模块内置 APK 与独立 APK 字节一致；下载同时提供 SHA-256 和正式签名证书信息。

## 验证范围

发布前执行 Android 单元/界面回归、lint、原生与 Shell/Python 回归、正式签名及版本检查、模块内外 APK 一致性，以及 Android 模拟器上实际签名包的安装、启动和覆盖升级。发布后核对 Release 与下载镜像实际字节，再更新 OTA。

记录详情页的逐项删除、HyperOS 等厂商 ROM 上的长期定时运行仍需实际设备观察；模拟器验证不能替代全部真机兼容性测试。
