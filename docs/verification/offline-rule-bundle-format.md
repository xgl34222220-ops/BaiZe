# Offline independent rule bundle v1

This round does not add networking or a new signing authority. The app accepts a local JSON envelope through Android's document picker and verifies it against the currently installed app's signing certificate public key. The publisher must sign with the existing matching publishing identity; no new credential is generated by the app.

Envelope: `{"payload":"<base64 exact UTF-8 JSON bytes>","signature":"<base64 detached signature>"}`.
Payload: `{"schema":1,"version":<positive integer>,"minAppBuild":<integer>,"files":{...}}`.
The `files` object must contain exactly app.rules, external.rules, hidden.rules, review.rules, custom.rules, deep.rules, risk-overrides.conf, rules.meta.env; values are base64 file bytes. RSA uses SHA256withRSA; EC uses SHA256withECDSA. The exact decoded payload bytes are signed, not reserialized JSON.

Limits: envelope 8 MiB, each rule file 2 MiB, decoded total 5 MiB; NUL/binary content and unknown paths are rejected. Signature, complete file set and application compatibility are checked before activation. A newer version is staged and published with atomic pointers; a verified prior version can be rolled back. A damaged active bundle falls back to bundled rules. Existing native risk/protection checks remain authoritative. This changes foreground App rules only, not module background rules.

Custom-rule preview is limited to an explicit shared-storage directory and optional `*` in a filename, followed by `|days`. It reads the current system index, shows matching paths, count and verified capacity, and refuses activation of incomplete scans. Enabling a rule does not authorize deletion; the regular scan/review/confirmation flow remains required. Index preview does not establish coverage of unindexed/private files.
