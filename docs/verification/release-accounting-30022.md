## 修复与统计口径

| 容量状态 | 含义 | 审计累计 |
| --- | --- | --- |
| `unknown` | 没有可信字节数；系统请求成功也不能推导容量 | 字节数为空，单独计无法测量的任务 |
| `retained` | 内容移入回收站或隔离区，仍占空间 | 保留容量单独展示，不加入删除容量 |
| `measured` 且为 0 | 本次可信结果确认为 0 字节，包括只移除空目录 | 显示真实 0，目录数量另计 |
| `measured` 且大于 0 | 已确认删除的文件内容字节数 | 按可信结果累计 |
| `partial` | 部分字节数已确认，其他结果无法测量 | 只累计已确认部分，同时标注不完整 |
| `not_applicable` | 扫描、归类移动、恢复或规则审核 | 不计释放容量 |

执行状态与容量状态独立：受保护、跳过、失败、取消和部分成功不会被替换成“释放 0”。
已经完成的可信删除量即使后续失败或取消，仍按实际证据保留。无返回值、JSON null、负值、
小数、布尔值和溢出字符串不会当作 0，也不会回退到扫描估算。旧记录中的歧义 0 标为无法测量，
读取兼容旧 TSV/JSONL，不凭空补测历史容量。

这里统计的是**已确认删除的内容大小**，不是存储设备可用空间的即时差值。系统可用空间更新、
文件系统分配和打开的文件句柄可能使物理空间变化不同；界面明确说明这一限制。

Root 返回的清理审计事件 ID 由工作台汇总引用，两条记录都保留，但容量只计一次。
历史与审计共用 Root 生成的唯一记录 ID、时间与结果说明。同秒执行的相同任务仍是不同记录。
缺失容量不作为 0 进入收益评分或平均容量的分母。
