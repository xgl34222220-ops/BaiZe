# 白泽 v2.1.0 Alpha 8

## 1. 扫描策略改回纯自动

- 清理页不再显示“扫描工作进程”策略卡片、吞吐、学习次数或手动串行/双进程选择。
- `scan_root_workers` 对普通用户固定保持自动模式；详细性能数据只保留在诊断日志中。
- 修复手动“垃圾扫描”绕过 `one-pass-scan.sh`，导致 `root-worker-profile.env` 永远没有样本的问题。
- 手动扫描和后台扫描都使用同一套自动策略与基准记录，避免 UI 显示与真实执行路径不一致。

## 2. 空文件与空目录修复

- 当前 NativeProfileEngine 会在 `Android/DCIM/Documents/Download` 等共享存储目录处提前剪枝，导致这些目录即使真实为空也没有 post-order 检查。
- 改为“内容子树仍受保护，但目录本身可进行只读空状态检查”。
- 清理前再次以 Root 权限确认：路径未变化、不是软链接、不是挂载点、列表可读取且仍为 0 项，才允许删除。
- 自动任务默认不反复删除系统会立即重建的标准目录；手动空项目扫描会显示并标注跳过/可清理原因。
- 扫描结果增加“未清理原因”，区分非空、不可读取、挂载点、保护目录、扫描后发生变化。

## 3. 文件归类

第一阶段做成独立手动工具，不加入自动清理：

- 分类：图片、视频、音频、文档、安装包、压缩包、电子书、其他。
- 默认只扫描共享存储根目录、Download、Documents、Bluetooth 等用户文件入口；排除 Android/data、Android/obb、应用私有目录、相机原始目录和隐藏系统目录。
- 先扫描并生成不可变移动计划，用户确认后才移动。
- 目标默认位于用户选择的“白泽归类”目录，各分类建立子目录。
- 同名文件不覆盖，使用安全重命名；跨文件系统时复制、校验大小与摘要后再删除源文件。
- 每次归类保存操作清单，支持撤销；源文件或目标目录在确认后变化时跳过。
- 首版不自动按内容猜测，不读取私人文档正文，仅使用扩展名、MIME 与文件头做类型判断。

## 安全边界

- 文件归类与垃圾清理使用不同的任务、快照和历史记录。
- 不允许 UI 提交任意源路径作为移动授权；移动目标必须来自服务端扫描计划。
- 不覆盖现有文件，不越过选定存储根，不跟随软链接，不跨越挂载点。
