# 白泽 v2 架构

## 分层

- Android App：MIUIx/Material 双皮肤、Monet、通知、计划配置、历史记录和人工确认。
- libsu RootService：AIDL 权限边界、扫描快照、模块状态和实际结果回传。
- Root 模块：扫描器、不可变清单删除器、统一累计账本、调度器和诊断。
- `/data/adb/baize-v2`：配置、类型化排除规则、事件账本、累计统计、最近 100 次明细和短期快照。

## 清理事务

1. 扫描生成带身份信息和风险等级的不可变快照。
2. App 展示同一快照的候选结果。
3. 用户确认后直接消费该快照，不执行第二次扫描。
4. 删除端复核元数据、白名单、路径、挂载点和风险边界。
5. 实际删除结果以幂等事件写入 `clean-events.tsv`，再归约生成 `totals.env`。

深度任务支持按游标恢复；事件 ID 包含快照与游标区间，重试不会重复累计。

App 进程只保存快照句柄、到期时间、分页和选择状态；Root 持久化候选逐文件清单。进程重启只恢复原事务，不用实时目录重新生成删除名单。单个文件必须继续匹配 device、inode、类型、大小、mtime 和 ctime；目录出现新子项时整项失败关闭。

## 排除与多用户

- `exclusions.json` 是唯一可编辑事实源，记录类型、值、清理作用域、Android 用户、原因、来源、过期时间和稳定 ID。
- `whitelist.<scope>.conf` 是缓存、深度、卸载残留、APK、整理和存储工具的兼容编译产物。
- 路径排除只支持明确的子树语义；关键根目录不能作为自定义排除项。
- 卸载残留按用户执行 `cmd package list packages --user`，并要求核心 `android` 包存在。列表缺失、用户未解锁或查询失败时不产生可删除候选。

## 存储工具与隔离

- 存储分类、大文件和重复文件共享增量索引，并公开 `scanned/reused/partial/locked/missing` 覆盖状态。
- 重复文件按大小、首尾快速 SHA-256、完整 SHA-256 分层；路径以 Base64 传递，文件名中的制表符或换行不会破坏报告。
- 大文件与重复文件默认只读展示，不进入自动清理链。
- 高风险隔离使用同文件系统原子移动，元数据经历 `pending -> ready`，有容量上限、冲突恢复名和到期清理。

## 调度

- Root scheduler 是配置、到期时间、公平队列、锁和恢复的唯一真相源。
- WorkManager 从 `Application` 注册，只负责在系统允许时唤醒 Root scheduler。
- 15 分钟周期任务是兜底；Root 返回的下一到期时间另建一次性 WorkRequest，执行后继续链式安排。
- 缓存、空项目、规则、碎片、深度和文件归类分别配置。
- 定时深度扫描强制关闭 high/critical；删除器 `safe-only` 再次执行同一限制。
- 深度和碎片任务在电池温度达到阈值时延后，并记录 `temperature_hold=1`。

## 统计

- `clean-events.tsv` 是模块清理的追加式事实账本。
- `clean-events-base.env` 保存升级前累计基线。
- `totals.env` 由基线和事件归约生成，不依赖最近历史反推。
- `history.tsv` 只保留最近 100 次展示明细，清空明细不清空生命周期累计。
- App 原生事务在 RootService 边界记账；模块事务直接调用同一个记录器，界面不再重复累计。
