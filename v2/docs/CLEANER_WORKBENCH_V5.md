# 清理工作台 v5：实现与对照

目标：以白泽 App 为完整清理产品，模块只承担定时自动化。界面沿用河图的配色、字体、卡片、留白与系统安全区域。所有文件管理能力保留用户的选择权。

## 本轮实现

| 流程 | 本轮变化 | 统计与边界 |
|---|---|---|
| 存储分析 | 分类占比、颜色分段、点击分类查看文件，返回分类概览 | 统计已索引的共享文件，不冒充整机空间 |
| 大文件 | 10 / 100 / 500 MB 门槛，类型筛选，名称/路径/应用搜索，大小/最新/最早/名称排序 | 大文件不等于垃圾，不默认删除 |
| 文件明细 | 来源目录、Android 包所属目录的应用名称、修改时间、完整路径、系统打开文件 | 只依据明确包目录关联应用，不凭文件名猜所属 |
| 批量选择 | 当前结果全选/取消，固定底栏展示已选数量与容量 | 筛选变化重置选择，防止误带入隐藏文件 |
| 重复文件 | 大小初筛、前缀过滤、完整 SHA-256 校验，显示分阶段进度，可停止 | 不再静默只检查前 12,000 个候选；每组保留至少一份，删除前重新核对内容 |
| 索引与任务 | 查询可取消，ViewModel 保留运行任务，读取失败与空结果分开 | 索引 120,000 项上限明确提示；不吞掉权限或提供者异常 |
| 安装包 | 应用名称与版本、已装/较旧/较新/未装/未识别，状态筛选、搜索、批量选择 | 读取失败与分包不伪装成“未安装”；版本比较不代表签名兼容 |
| 缓存扫描 | 按线程完成顺序反馈进度，停止后退出剩余遍历，如实标注测量是否完整 | 没有用未经实测的“加速倍数”宣传 |
| 视觉 | 延续全页面统一的河图样式，新分析图、分类卡、筛选器和选择底栏使用同一套组件 | 继承状态栏/挖孔安全区与滚动裁切，包含深色、小屏和大字体检查 |

## 参考范围与来源

用户提供的 46 秒录像：第一款显示为“安卓清理君”；第二款依据画面与图标判断为“存储空间清理”。从录像吸收扫描分项进度、文件来源、分类钻取、安装包状态筛选与批量操作。两款 App 在录像中先后清理，起始数据不同，不能据其显示的清理量比较清理能力。

以下仅基于公开官方功能说明做能力对照，未在用户两台手机上完成同条件实测。不能据此声称“超过所有清理 App”。

| 参照 | 官方公开能力 | 白泽吸收与对应 |
|---|---|---|
| [SD Maid SE](https://github.com/d4rken-org/sdmaid-se) | 残留查找、应用/系统清理、存储分析、查重、调度、Root/Shizuku | App 主体 + 可选自动化，清理规则、快照、归属、可控查重；不复制品牌或资产 |
| [Files by Google](https://support.google.com/files/answer/9713869?hl=en) | 垃圾清理引导，以及大文件、重复文件、下载、截图等整理入口 | 强化“分类—查看—选择—确认—结果”的短流程 |
| [CCleaner Android](https://www.ccleaner.com/ccleaner-android) | 垃圾/缓存清理与空间管理 | 聚焦可理解的结果和少步骤操作，不采信未经验证的性能营销数值 |
| [Avast Cleanup Android](https://www.avast.com/cleanup-android) | 缓存与媒体整理、类似照片评审、图片压缩、自动清理 | 自动化与手动文件评审分离；类似照片和压缩留待单独验证实现 |
| [DiskUsage](https://github.com/IvanVolosyuk/diskusage) | 按目录与文件大小可视化空间占用 | 先实现可点击分类及实际文件列表；完整目录树图仍待建设 |

## 下一阶段应以实测决定优先级

1. 在一加与 HyperOS 真机使用同一批文件，分别记录扫描覆盖、耗时、峰值内存、误报/漏报、停止响应和实际释放量；保留清理前后快照，不以页面数字代替验证。
2. 补全不依赖媒体索引的可控目录分析、缓存归属说明、增量结果缓存及扫描覆盖诊断。文件访问范围必须准确提示。
3. 微信/QQ 等专项需按真实版本验证目录规则，明确缓存、下载和用户内容，不把聊天附件一概归为垃圾。
4. 相似照片需可解释的分组与人工保留；压缩、回收站、云端功能需独立设计，当前版本不宣称提供。
5. 整体清理工作台继续统一扫描阶段、实际结果、可恢复能力与长期记录，并保持模块仅负责后台自动化的边界。

## 验证内容

新增内容级测试覆盖：相同前缀不同尾部、索引大小过期、同一路径重复索引、校验中修改、分块取消与关闭流、筛选后选择范围、自定义保留副本、分类钻取、应用关联与 APK 版本筛选。

新增实际 Compose 渲染检查覆盖：分析概览与分类详情、320 dp 深色大字体大文件页面、安装包版本筛选；继续运行已有的全部界面与系统栏安全区测试。

CI 渲染使用模拟数据验证布局，不能代替真机扫描性能或厂商权限兼容测试。
