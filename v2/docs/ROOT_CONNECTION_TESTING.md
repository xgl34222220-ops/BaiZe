# Root 连接恢复验证

## 自动化覆盖范围

```sh
cd v2
./gradlew :app:testDebugUnitTest
./gradlew :app:lintDebug :app:assembleDebug
```

`RootServiceRecoveryTest` 使用 Robolectric 和本地 fake Binder 验证客户端状态机：

- 收到启动广播后 `connect` 或 `bind` 失败，请求得到明确失败通知，同一连接可以重试。
- 多个待绑定服务中，一项失败或被回调取消，不留下无超时保护的请求。
- 断开回调同步重新绑定时，不删除新建立的连接。
- daemon 与普通服务的启动状态和超时互不清除。
- 已取消、已超时且尚未执行的启动任务不会再输出启动命令。
- 失败原因区分 Root 不可用、启动失败、启动超时、Binder 握手失败与空绑定。
- 重复绑定同一连接不累加引用，解绑仍能释放服务。
- Android 8 的普通 `ServiceConnection` 仍能收到失败回调。

这些测试不创建真实 Root 进程，不证明厂商 ROM 下的 IPC、授权和进程保活正常。

## 真机验收

使用测试设备和无重要数据的测试任务。覆盖 Android 16，以及项目支持的 Magisk、KernelSU、APatch；记录具体系统、管理器、App 和模块版本。无需为连接验收执行真实文件删除。

| 场景 | 操作 | 预期 |
|---|---|---|
| 正常启动 | 已授权，冷启动 App | 两项服务连接、模块校验完成；版本一致或明确报告未知字段 |
| 未取得 Root | 拒绝授权后冷启动 | 不无限连接；说明未取得 Root，不把它记录为已确认服务崩溃 |
| 启动无回复 | 在受控测试环境延迟/阻止启动广播 | 等待广播的请求超时；恢复条件后可手动重试 |
| 绑定中退出 | 测试服务广播后、完成绑定前退出 | 不遗留永久等待；显示绑定失败，后续重试可完成 |
| 已连接后退出 | 终止测试 Root 服务进程，不操作真实清理任务 | 记录连接断开；有限自动恢复，耗尽后允许手动重试 |
| 页面切换 | 快速切换首页、后台与前台 | 不重复绑定积累引用，不因旧回调覆盖新连接状态 |
| 覆盖升级 | 安装测试新版，保留数据，再连接 | 显示实际运行 Root 代码的版本；旧服务或模块不一致时提示更新/重启 |
| 离线诊断 | 服务断开后打开并复制诊断 | 可读取连接记录，缓存版本带观察时间，不冒充当前在线版本 |
| 旧异常保留 | 留一份旧 Root/App 异常后开始新连接会话 | 明确标注历史记录；不能仅因有旧堆栈就认定本次崩溃 |

验收报告须保留故障发生时间和对应的连接/异常记录。没有 Java 异常记录不能排除进程被系统终止；必要时使用同一时间段的 logcat、tombstone 或进程退出证据。分享前检查并移除日志中的私人文件路径等信息。

## 尚未解决的边界

- 30 秒启动 watchdog 与握手共用客户端主线程，不能打断已经阻塞的同步 Binder 调用。
- 取消只阻止尚未执行的启动任务，不撤销已经启动的进程。
- 启动广播没有逐次尝试的令牌，不能据此判定迟到广播属于哪一次启动。
- 版本不一致只做诊断提示，不自动停止 daemon，避免中断仍在执行的后台任务。

不要把“客户端状态机测试通过”写成“所有真机断连问题已解决”。
